# 流程与地图配表

Unity 2022.3.33f1c1。运行入口是 `Assets/Scenes/FlowGame.unity`，原 Boot 与固定五房路线保留。

## 开始使用

1. Unity 菜单「超高速行者 → 流程与地图 → 打开流程白盒」，点击 Play。
2. 「配表窗口」编辑全局流程、箱庭、差分、地图池与循环。
3. 默认配置在 `Assets/Settings/FlowExamples/RunFlow.asset`。右上角显示混乱度；左下角开发面板显示房间、后继、循环、记录点和错误。
4. 普通地图与变化地图都会参与生成。在变化地图里击碎入口附近的稳定装置提升混乱度，到达 100 后生成最终房，到最终房出口通关。

首次缺少样例时可用「生成白盒配表示例」。生成器从团队白盒导出五份独立模板和导航数据，不改原白盒；再次运行保留已有模板和配表。示例中的灯光、装置位置、叙事文字和池分类用于技术验收，可继续编辑。

## 配置关系

`RunFlowConfig → 地图池 / 循环 → 差分 → 箱庭 → 房间模板`

- 箱庭编号表示地图资源，差分编号表示池中的抽取元素，运行时实例编号表示一次实际访问。同一模板可以同时存在于不同实例场景。
- 普通混乱度默认 0～100；0～30 为低段循环，31～79 普通生成，80～99 高段循环，100 最终房优先。
- 循环固定抽取 3 或 6 个普通房与 1 个变化房，之后按固定序列重复。混乱度离开区间后退出；这是内容序列循环，不要求地图几何闭环。
- 默认每次实际进入后，差分权重乘 1/4；预加载不计访问。整局重开清零，记录点恢复会恢复规划器随机状态、访问记录与循环游标。
- 稳定装置默认由差分给出 10 或 15 增量。每次访问最多结算一次；同一次访问死亡恢复仍保留已破坏状态，循环中的新访问重新创建装置。
- 当前房间不会在战斗中突然切换几何；恢复时按最新混乱度选择本箱庭差分。尚未进入的后继会重新检查资格。
- 特殊负数和 999 路由已有配置入口，示例默认关闭，未制作对应内容。

地图池 CSV 支持带 BOM 的 UTF-8、引号、逗号和换行。导出包含池编号、差分编号、资产 GUID、权重和启用标志。导入先校验全部行，再一次性写入 SO；不能用 CSV 的未知编号隐式创建资产。运行时统一读 SO。

## 接入新地图

1. 房间根节点挂 `FlowRoomTemplate`，缩放保持 1。入口和出口是根节点的直接子节点；入口朝向房内、出口朝向房外，锚点位于地板处。
2. 指定门板、净宽高、局部几何包围盒、局部掉落高度、导航数据与叙事 TextMesh。导航以模板原点和姿态烘焙，运行时按实例变换注册。
3. 放置 `FlowCheckpoint`，填写稳定编号、优先级、半径及是否允许回覆盖。每房入口都放记录点时，常态仅保留当前和后继；第一记录点提交前仍保留前驱。
4. 可切换物件、敌人及生成器放在 `FlowContentGroup` 下。敌人与生成器勾选「仅当前房间启用逻辑」，避免预加载时开始刷怪或攻击。
5. 创建箱庭及 1～6 个差分，关联模板并覆盖需要的混乱度区间。差分选择内容组、叙事及灯光参数；变化房启用稳定装置内容组。
6. 登记地图池和权重，再运行「检查当前配置」与「生成预览」。实际空间合法性在运行时检查，无法装配时保护门关闭并给出错误，可重试后继装配。

各差分保持相同的门位与记录点编号。门区的基础地板放在公共几何中，差分内容组不能遮挡门洞或移除记录点脚下的支撑。

门连接会平移、旋转后继房间，保留玩家、相机和速度；连接地板保持连续碰撞。动态显示副本扣除与两端房间共面的部分，前驱卸载后恢复被遮挡的补面。原始 Mesh 和 Collider 不做破坏性修改。

记录点按进入边缘触发，支持高速扫过。高优先级默认不能被低优先级覆盖，特殊动线可勾选回覆盖。死亡扣除混乱度后重建记录点房间、复位动作及运动状态；非致死裂隙掉落只扣血，不扣混乱度，战斗无敌帧不能抵消裂隙伤害。

## 验证

PowerShell 7 在仓库根运行：

```powershell
./Tools/map-flow/validate.ps1 -Stage Compile
./Tools/map-flow/validate.ps1 -Stage Examples
./Tools/map-flow/validate.ps1 -Stage EditMode
./Tools/map-flow/validate.ps1 -Stage PlayMode
./Tools/map-flow/validate.ps1 -Stage MapBaseline
```

验证工程位于 `Tools/map-flow/obj/Validation`，不占用正在编辑的工程。日志与 XML 同目录，受 Git 忽略；验证不会把副本的 ProjectSettings 或包设置回写到工程。运行测试前需要示例资产，仓库已提供，可用 Examples 在副本中补建。

EditMode 覆盖混乱度边界、权重分布、长期衰减、循环、随机状态恢复、CSV 原子性和共面裁剪。PlayMode 使用真实白盒，覆盖复活差分、记录点保护及优先级、装置、独立实例、120m/s 过门、50 次换房、整局重开与通关。MapBaseline 重跑原地图模块的 13 项回归，高速测试使用独立移动参数副本。

2026-10-17 验证结果：27 项 EditMode、15 项流程 PlayMode、13 项原地图回归通过，共 55 项、0 失败。高速用例连续跨过 12 道动态房间门；恢复用例同时检查朝向以及模板外动态对象的清理。

本版通过预加载房间预制体并放入独立场景容器管理实例。实例场景可卸载，源素材仍由配表引用保留；未引入额外资源流式加载包。自动测试不代替完整跑酷动线、敌人难度、正式图形设备的画面与性能验收。
