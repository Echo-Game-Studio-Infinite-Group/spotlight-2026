# 混乱度与箱庭差分：第一阶段接入

依据：炸虾在 2026-10-15 提供的六节《流程与地图生成定稿》。本模块是第二项任务的第一阶段，不代表整个随机地图流程已经完成。

## 当前范围

- 全局混乱度由 WhiteboxGame 内的 ChaosManager 持有，换房不丢失，整局重开清除。
- 正常值 0—100；显式接口支持负数、999。999 不被当作普通通关值，也不执行未定稿的普通死亡扣分。
- 右上角显示数值；既有音频调试面板在本场景暂时隐藏，离开时恢复，不停止音频。
- 入口两盏稳定装置使用现有 IAttackDamageReceiver、动作序列及 Hitbox，实际挥刀击碎后分别 +10、+15。
- 后继预加载房的装置不能提前获取收益；同一装置本局去重，默认死亡和房间卸载后仍保持已碎。
- 每房支持 1—6 个差分预制体和独立的闭区间阈值；编号重复、区间重叠或无预制体的 Configure 请求会被拒绝。
- 共用白盒主体保留，只实例化选中的差异部分；回点时从预制体重新建立差异内容，而非保留已修改的运行实例。
- 当前房默认进入、回点时刷新；后继预加载内容随混乱度更新。可在 ChaosRoomVariants 勾选即时变化，仍需策划确认正式时机。
- 普通死亡 -10，下限 0；回记录点后按新值选择差分，恢复配置的血量，并继续使用同一玩家和相机。
- 非致命掉落只扣血回点，不扣混乱度；致死掉落只计一次死亡。暂停或跨门切换期间延后回点处理。
- 支持靠近自动触发的记录点、同房优先级和显式允许低优先级再次覆盖；当前白盒只实际放置了入口记录点。

## 怎样运行、验收

1. 使用 Unity 2022.3.33f1c1 打开本工程根目录，双击 Assets/Scenes/Boot.unity，再播放。
2. 教程出生位置前方左右各有一盏黄色装置，靠近并用鼠标左键攻击，检查右上角增加 10 或 15，完整灯变为碎片。
3. 按 Esc 释放鼠标，点击右上角“展开联调工具（非正式 UI）”。面板展开期间暂时借用并关闭游戏输入，避免点按钮同时挥刀；收起后恢复。
4. 点击“设为 35”，再点“回记录点并刷新差分（不扣血）”，可见联调 B；设为 85 后回点可见 C，设为 0 后回点可见 A。
5. 设为 35 后点击“模拟致死”，应复活且数值变为 25，对应 A。这会走 HealthComponent.Died 的实际处理，不是按钮直接改成 25。
6. 收起工具后正常跑图过门，验证混乱度保留、后继差分正确。联调设值按钮只用于验收，正式获取方式仍是击碎灯。

三种示例分别有不同数量/形状的物件、局部灯光和文字，标注为“非正式关卡内容”，不改变队友已有地板、碰撞、导航或门位。它们用于证明选择机制，不是队友每张地图的正式差分设计。负数和 999 在示例中仍落到普通占位内容，不代表特殊房间或特殊结局已制作。

## 参数及未定稿占位

规则资产：Assets/Settings/Chaos/ChaosRules.asset。

| 参数 | 当前值 | 性质 |
| --- | --- | --- |
| 普通上限、死亡惩罚 | 100、10 | 流程明确，可配置 |
| 循环资格区间 | 0—30、80—100 | 只输出条件，不自行组环 |
| 初始混乱度 | 0 | 联调默认，待正式确认 |
| 掉落伤害 | 20 | 联调占位，可配置 |

开启“死亡恢复灯”会清除此房装置奖励记录，因此允许再次获取混乱度；策划未确认前保持关闭。每个装置 RoomId/LampId 必须稳定且唯一，未来重复房间实例的编号策略需和地图生成方协商。

## 对接接口

- ChaosManager.Value、Changed(previous,current)：全局值及变化通知，供 UI、配表和流程读取。
- SetNormalValue：正常设值并限制在普通范围；不是正式获得混乱度的交互入口。
- SetSpecialValue：仅接受负数或 999，不自动生成特殊地图。
- TryBreakLamp(roomId,lampId,gain)：本局收益去重，正常上限保护。
- IsInLoopRange、NormalGoalReached：两种独立条件；混乱度 100 时都可能成立。最终房优先级由后续地图流程决定，本模块不擅自定稿。
- ChaosRoomVariants.Configure：接收 1—6 项差分定义。进入/回点使用 Refresh，强制重建使用 Refresh(true)。
- ChaosRunController.TrySetCheckpoint：处理记录点优先级；RequestCheckpointReturn：不扣血的回点请求。
- ReturnedToCheckpoint(bool died)、CheckpointChanged：提供存档和表现层的后续对接事件，不是完整存档系统。

差分预制体可包含敌人配置，但程序不会替策划生成正式敌人表。动态生成器必须将生成物归到本差分的生命周期内，不能把房间卸载后仍存活的对象留在常驻池或场景根。当前实际白盒没有敌人差分，不能据此宣称敌人刷怪/重置已完整联调。

## 已有代码改动

- PlayerRespawn 新增 Falling 事件：有本模块订阅时交给它处理；无订阅的旧场景保留原先掉落传送行为。
- HealthComponent 增加 Reset(health) 重载支持配置的复活血量；原 Reset() 仍恢复满血，维持既有调用语义。
- WhiteboxGame 增加 ChaosSystem、ChaosHUD 和玩家实例上的 ChaosRunController，不修改原 Player.prefab。
- 五个 Whitebox 房间各增加独立联调根节点，不覆盖原始地图 ZIP、导入预制体或接缝网格。
- 新增 ChaosWhiteboxSetup 编辑器菜单：超高速行者 → 混乱度 → 接入现有团队白盒。已存在联调根和资源会保留，重复执行不再添加一套。
- 如果运行原“接通团队白盒默认路线”工具重新生成了场景，需要再运行本模块接入菜单。

## 验证

测试位于 Assets/Tests/MapStreaming/ChaosMechanicsTests.cs，与原加载测试使用 GameJam.Tests.MapStreaming 程序集。

涵盖实际攻击输入→动作→判定盒→打灯、10/15 增量、预加载房收益保护、区间/特殊值、前后房差分、致命和非致命掉落、死亡去重、回点内容重建、灯状态保留、记录点优先级及物理触发、整局重开、暂停和配置校验。

最近一次完整回归为 **31/31**（18 项混乱度 + 13 项加载/接缝），结果在本地 Logs/ChaosAndStreamingFinalTests.xml。使用实际 D3D11 图形设备运行，测试器正常退出；包含联调面板输入借用和恢复测试。Logs 是本地产物，不提交到 Git。

另由 ChaosWhiteboxPreview 离线渲染了三种占位差分的实际 URP 图像，输出 Logs/ChaosWhiteboxVariantA/B/C.png。这里只检查物件、灯、碎片和标注，不冒充完整游戏画面或正式 UI 验收。标注尺寸调整不影响上述运行时规则。
