# 地图无缝加载验收

团队真实白盒与 Boot 入口已另行接通，正式接入说明见 Assets/Scenes/WhiteboxStreaming/接入说明.md。本目录保留为独立回归样例。

Unity 2022.3.33f1c1，打开本目录的 MapStreamingDemo.unity 后点击 Play。沿蓝色、橙色、绿色通道向前走即可通过两个门。WASD 移动，鼠标转向，空格跳跃，Esc 释放鼠标。

左上角显示当前房间和已加载场景，Hierarchy 中也能看到同样的结果：

| 位置 | 应加载的房间 | 应卸载的房间 |
| --- | --- | --- |
| 蓝色房间 1 | 1、2 | 3 尚未加载 |
| 穿过第一道门，进入橙色房间 2 | 2、3 | 1 |
| 穿过第二道门，进入绿色房间 3 | 3 | 1、2 |

MapStreamingDemo 始终保留唯一玩家和相机。切换不传送角色、不重置速度。目标房间未准备好时保护门保持关闭；通过后回头门关闭，避免退回已卸载区域。

## 样例和正式地图的区别

BOX_S1013 的三个白盒已分别保存到三个房间场景，原始场景未修改。白盒保持原尺寸，平移到验收通道旁。样例停用了房间内敌人，排除导航和战斗对加载验收的干扰。彩色通道用于验证场景加载，正式关卡仍需关卡同学确定真实入口、出口和门的位置。

重新生成样例：菜单“超高速行者 → 地图无缝加载 → 生成三房间验收场景”。此操作会重建本目录生成的四个场景；正式关卡请另存为其他名称。打开样例可用同菜单下的“打开验收场景”。

## 给地图配表的接入接口

- 常驻场景的 MapBootstrapper 填首房名称和玩家引用，负责加载地板期间暂停运动。
- 每个房间只放几何、敌人、机关等内容，不放重复的玩家和相机。
- 房间中添加 MapRoom，配置下一房间场景名。只有当前房间会触发后继预加载，预加载不会递归加载全图。
- 出口放 MapRoomGate，指定下一房间和带 Collider 的门物体，下一房加载后放行。
- 进入下一房的触发器放在门后，角色整体通过后才触发。添加 MapRoomPortal，来源填前房名称，目标填当前房名称；Box Collider 勾选 Is Trigger，Rigidbody 使用 Is Kinematic 且不使用重力。
- 房间场景必须添加到 Build Settings，并使用唯一场景名。
- 配表工具也可直接调用 MapManager.Instance.PreloadRoom(name)、TryEnterRoom(previous, current)。RoomLoaded、RoomEntered、RoomUnloaded 用于订阅结果；返回 true 表示请求被接受，最终状态通过事件或 IsRoomReady、CurrentRoomSceneName 检查。

这是独立验收入口，未修改已有 Boot 启动目标。停止并重新 Play 可以从头验收。

## 自动化验证

Window → General → Test Runner → PlayMode，运行 GameJam.Tests.MapStreaming。

覆盖首房/后继加载、重复请求、白盒网格保存、两道真实触发器切换、玩家/相机身份和速度连续性、未加载时关门、错误场景名和常驻场景保护。
