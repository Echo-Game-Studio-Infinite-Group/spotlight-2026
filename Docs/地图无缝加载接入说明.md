# 地图无缝加载与团队白盒接入说明

本文面向地图配置、关卡制作及程序联调，记录炸虾在 `feat/map` 分支的房间加载实现、团队白盒接入和接缝修复。地图来自队友已有白盒，不是重新制作关卡。

**默认入口变化：Boot 的目标已从 TestScene 改为 WhiteboxGame。** 使用本分支从 Boot 播放，会进入下述五房间默认流程。原 MainGame、BOX_S1013、地图 ZIP 和玩家预制体保留，未被覆盖。

## 1. 接入范围与运行入口

使用 Unity **2022.3.33f1c1**，未升级编辑器、渲染管线或新增第三方插件。

1. 打开本仓库根目录，不要在工程里新建同名子项目。
2. 双击 [Boot 场景](../Assets/Scenes/Boot.unity)，点击 Play。
3. Logo 结束后加载常驻场景 WhiteboxGame，再以 Additive 方式加载教程房。
4. 首房准备完成后恢复玩家控制，提前加载后继；通过真实门洞后的触发区后，进入下一房并卸载上一房。

Unity 菜单 **超高速行者 → 地图无缝加载 → 打开团队白盒游戏** 也会打开 Boot。左下角面板显示当前房、加载场景、切换状态和错误；它是开发验收 HUD，不是正式游戏 UI。

当前顺序尚未由团队最终定稿，按炸虾确认的临时默认路线接通：

**教程 → 01 → 02 → 03 → 04**。

| 角色 | 场景 |
| --- | --- |
| 启动与 Logo | Boot |
| 常驻玩家、相机、灯光及启动组件 | WhiteboxGame |
| 可独立加载/卸载的房间 | Whitebox_Tutorial、Whitebox_Room_01～04 |

正式白盒场景位于 [WhiteboxStreaming](../Assets/Scenes/WhiteboxStreaming)。[MapStreaming](../Assets/Scenes/MapStreaming) 中的三房间样例仅用于回归测试，不是当前入口。

正常稳定状态主要保留“当前房 + 后继房”。切换时先发起下一后继的预加载，再等待旧房卸载，因此异步阶段可能短暂同时存在三个房间；并非强制最多两个场景。

过门不传送玩家，不重新创建玩家/相机，不主动清空速度。重开整局则会重建常驻入口和玩家，这是另一个流程。

## 3. 团队白盒资源与真实门位

原始资源来自团队已上传的 [LevelTest_Cdwy 地图 ZIP](<../Assets/Scenes/LevelTest_Cdwy/LevelTest_Cdwy (2).zip>)。将教程、01～04 及依赖导入 [TeamWhitebox](../Assets/Prefabs/Maps/TeamWhitebox)，使用独立副本，不覆盖原 ZIP 或其他已有场景。

- 相同 GUID 的已有资源直接复用，避免重复 GUID 和覆盖队友资产。
- 部分 ProBuilder 对象保留了原始顶点和三角形，但缺少运行时 Mesh。根据原始数据恢复网格、UV 和缺失的 MeshCollider 引用，包括嵌套楼梯、箭头等依赖。
- 清理导入副本上的 Missing Script 引用；没有安装 ProBuilder 或其他新包。
- 恢复网格保存于 RecoveredMeshes 子目录。关卡形状和美术资源仍来自团队原始制作。
- 每个生成房间烘焙独立导航数据；当前导入的房间预制体没有敌人实例，未在本次填写敌人配置。

房间实例只作刚性旋转、平移，不整体缩放。门位映射如下：

| 房间资源 | 入口对象 | 出口对象 | 后继场景 |
| --- | --- | --- | --- |
| BOX_S教程 | Door | Door (1) | Whitebox_Room_01 |
| BOX_S01 | Door | Door (1) | Whitebox_Room_02 |

## 4. 加载接口与调用约束

统一通过 MapManager 调用，不在地图配表或关卡脚本里各自再维护一套 SceneManager 状态。

| 接口/状态 | 语义 |
| --- | --- |
| `MapManager.Instance` / `Exists` | 获取常驻加载器，或只检查是否已有实例。 |
| `RegisterPersistentScene(scene)` | 注册保存玩家/相机的常驻场景；首次注册名称也作为重开入口。 |
| `TryLoadInitialRoom(name)` | 提交首房进入请求。 |
| `PreloadRoom(name)` | 发起后继 Additive 加载，重复请求复用同一任务。返回 true 不代表加载已经完成。 |
| `IsRoomReady(name)` | 场景有效、已加载且不在卸载中，才算可用。 |
| `TryEnterRoom(source, target)` | 提交进入目标房请求；目标就绪后设置活动房、准备后继并卸载来源房。 |
| `TryUnloadRoom(name)` | 受保护的主动卸载接口；常驻场景、当前活动房等不能被误卸载。 |
| `TryRestartMap()` | 提交重开请求，等待后台加载/卸载结束，再以 Single 方式重载常驻入口。 |
| `CurrentRoomSceneName` / `IsTransitioning` / `LastError` | 当前房、切换锁与最近错误。 |
| `RoomLoaded` / `RoomEntered` / `RoomUnloaded` | 加载就绪、进入完成、卸载完成通知。 |

注意：

- `TryEnterRoom` 返回 true 表示接受请求；异步完成应看事件和状态。已加载目标也可能同步完成，不能把 Coroutine 返回对象当作切换锁。
- `RoomEntered` 在切换完成、旧房卸载结束后通知。后继的预加载可能仍在进行。
- 目标未加入 Build Settings 时拒绝请求并保留当前房间，不先卸载旧房再报错。
- 只有真正进入的房间会准备后继。被预加载房间不会自动递归加载后面的全部地图。
- 不使用 `allowSceneActivation = false` 挂起队列，以免阻塞后续异步加载/卸载。
- 进入首房前，Bootstrapper 暂时关闭 CharacterController 和游戏输入，不抢占 PlayerActionRunner 已持有的 Motor 模拟权。

## 5. 接入或调整房间的方法

当前场景已配置完成，日常运行只需打开 Boot，不需要重新生成。

后续新增/替换房间时，应同时准备以下内容：

1. 房间保存为独立场景，并加入 Build Settings。
2. 玩家、相机和全局系统保留在常驻场景，不复制进每个房间。
3. 配置 MapRoom 的后继、入口/出口、重生点和掉落高度。
4. 相邻房间在同一世界坐标下对齐门洞，并提供连续碰撞支撑。
5. 门后配置 MapRoomPortal 的来源房、目标房及触发体；通过 Configure 装配或检查 Is Trigger、运动学 Rigidbody 与关闭重力。
6. 配置后继加载保护门，以及进入新房后的回头门。
7. 需要去重的显示副本随所属/相邻房间生命周期切换，不能删除碰撞或直接覆盖原始 Mesh。

**不能只改 NextRoomSceneName 来交换现有房间顺序。** 当前五房已经按默认顺序拼接到世界坐标，顺序变化也必须同步重拼门位、来源/目标、触发区和接缝。

自动装配使用 TeamWhiteboxSetup 的 RoomAssets、EntryDoors、ExitDoors 定义路线和门对象。修改并重新生成前，先保存或提交手工关卡编辑。

## 6. 重开、掉落与角色保留

- `GameManager.RestartLevel` 在流式地图中走 `MapManager.TryRestartMap`，回到 WhiteboxGame 并重建玩家、加载教程。非流式场景保留旧重开路径。
- 进入房间后，Bootstrapper 把 MapRoom 的 RespawnPoint、FallDeathY 写入 PlayerRespawn。
- 房间高度不同，不能全程使用旧的固定 -10 掉落线；也不能掉落后回到已卸载的教程出生点。
- PlayerMotor、相机脚本、玩家预制体、动作和战斗算法未重写。过门与重开分别验证，不能把“重开重建玩家”误认为“过门替换玩家”。

## 7. 门口闪烁修复

原接入处的棕白闪边和白蓝三角交替来自共面重复显示：连接地板伸入门槛，门槛覆盖原地面，教程的斜向白色地面还伸入下一房蓝色地面。

处理方式：

1. 连接地板和护栏只覆盖两个真实门洞外沿之间的间隙，不重复铺入房间。
2. 门槛显示止于门沿，BoxCollider 仍向两侧各延伸一米，补住原白盒薄片地面的局部碰撞缺口。
3. WhiteboxSeamMeshBuilder 对同向共面三角形裁剪，生成独立显示副本；原始网格、材质分组、UV 和碰撞保留，不靠抬高地板掩盖问题。
4. 跨房间的原始地面叠压优先保留后继房地面，裁掉前房显示副本的重复部分。
5. MapSeamSurface 在邻房存在时显示双房间去重结果；邻房卸载后恢复本房需要的显示面，避免去重后留下空洞。

派生显示网格保存在 [SeamMeshes](../Assets/Scenes/WhiteboxStreaming/SeamMeshes)。没有修改原始地图网格资产，也没有改变 MeshCollider 指向的原始碰撞。

本次没有清理整个关卡内部所有原始物体相交。例如 Room02 中 Cube (2)/Cube (5) 的局部同房间重叠保留；测试约束的是本次新增补面与跨场景重复层。

截至 2026-10-15，实现版本 ad8ca53 的 `GameJam.Tests.MapStreaming` 共 **13 项 PlayMode 测试通过，0 失败**：

| 测试文件 | 项数 | 覆盖内容 |

| [TeamWhiteboxTests](../Assets/Tests/MapStreaming/TeamWhiteboxTests.cs) | 6 | Boot 启动、真实门对齐/地板、四道门按 120m/s 对应位移通过、整局重开、当前房掉落重生、接缝回归。 |

重现步骤：

1. 停止当前播放，保存场景。
2. 打开 **Window → General → Test Runner → PlayMode**。
3. 选择 MapStreamingTests、TeamWhiteboxTests，或对应的 GameJam.Tests.MapStreaming 程序集，运行测试。
4. 查看 13 项结果；不要把工程其他测试的通过数误算进本模块。

接缝回归在四道门左、中、右三条路径共检查 **798 个点**的可见地面、新增/跨场景重复层和碰撞支撑，并检查上一房卸载后补面恢复及下一房入口地面。另使用实际 D3D11/URP 检查教程出口三个相邻机位，原棕白闪边及白蓝叠压三角不再出现。炸虾已反馈当前门口人工复查通过。

本地最近一次结果文件为 `Logs/WhiteboxSeamAcceptedTests.xml`，渲染检查图为 `Logs/WhiteboxSeamAfter0～2.png`。Logs 属本地产物，不纳入 Git；队友可自行重跑测试或调用 WhiteboxSeamPreview.Capture 生成图片，后者不能使用 -nographics。

验证边界：

- 自动跨门前先将角色放到出口附近，之后使用真实 CharacterController 移动通过触发区，不是在跨门时传送。
- 没有用测试完整玩通每房内部的跑酷路线，也不代替战斗、难度、美术和动画的完整人工验收。
- 13 项只指本地图模块，不代表本次运行了工程全部动作、战斗和音频测试。
- 尚未做正式性能基准；异步预加载不等于保证所有机器绝对零卡顿。
