# 《超高速行者》三组分工与 21 天交付计划（建议稿）

依据：策划案 v1.03、成员信息表及队长补充说明。
目标：D20 完成可提交版本并实际提交/交付；D21 只作提交故障与严重缺陷缓冲。

> 本文是待队长与成员确认的分工建议，不代表成员已承诺或已完成技术能力评估。未检查项目代码，以下是需求级拆解，不是对现有实现进度的判断。原始成员表与策划案不作修改。

## 一、先说结论

本轮建议交付一个 **5—8 分钟、可完整通关的高速移动战斗切片**：玩家可以通过跑跳积累速度，在战斗中利用高速攻击、滑铲与 parry 保持生存，通过战斗房和跑酷房抵达终点。

这是对 v1.03 的建议收敛，不是原案已有的流程承诺。**完整技能树、三类敌人和随机地图不能同时作为本轮保底交付。** 必须先证明兔子跳与高速战斗好玩，再增加内容。

- **程序组**：核心操作、战斗、敌人、房间流程、UI 与音频接入。
- **策划组**：规则定稿、参数表、灰盒关卡、数值调试与体验验收；兼职程序只做小范围辅助工作。
- **美工组**：模块化场景、最小角色/敌人资产、UI 与反馈资源，优先可读性，不追求资产数量。
- 没有独立测试岗位：策划承担功能与体验验收，程序负责修复与技术回归。

### 必须D2解决的设计歧义

1. **输入冲突**：Shift同时涉及奔跑、蹲伏、滑铲、侧闪；右键同时涉及加速、时停、推斩与连斩。haski负责输入优先级表；建议P0将滑铲/闪避分键，右键仅保留一个能量技能，具体键位经试玩确定。
2. **坐标系**：原案以xoy作地面、z作高度；项目路径提示Unity，但尚未核实工程。若用Unity默认坐标，需统一为XZ地面/Y高度，设计语义不变。
3. **能量单位**：按原案60 tick/s计算，v=2时每秒应加60点，空能量约3.33秒到200。v需要明确为相对地速的无量纲速度比，不能直接代入世界单位速度；实现不得直接按渲染帧累加。
4. **攻击/高速门槛**：高速普攻为0.8倍地速，积能为超过1倍，必须区分；不能把所有“高速”共用一个未定义布尔值。
5. **动作取消与判定顺序**：同帧parry、伤害、击杀、闪斩授权谁先结算；停止/落地何时清动量；队长批准一张简化表后再编码。
6. **时间效果**：parry时缓时长、玩家/敌人/粒子/音频受影响范围、暂停恢复优先级未明确；主动时停本轮剔除不能代替解决parry时缓。
7. **关卡与结算**：原案流程占位，需定义终点、失败、重开与检查点；本计划补足这些交付必需内容，不新增完整存档系统。
8. **平台与设备**：D1确认引擎版本、交付平台、目标硬件、分辨率/帧率目标与活动提交材料要求，不凭文件路径直接锁死实现方案。

## 九、风险与裁剪顺序

| 风险/触发点 | 处理措施 |
| --- | --- |
| 3C与战斗耦合高，D5仍不好玩 | 先保证跑跳、基础攻击、单近战敌人；冻结其他技能。由haski和绯云当天确定保留哪一条核心循环 |
| 原案高速普攻停动量依赖推斩等派生维持循环 | D6对不含复杂派生的版本做专项试玩；不能成立时由haski批准简化动量规则，并同步原案变更记录，不悄悄改手感 |
| 3D资产/绑定动画不足 | D2验证授权现成资产或简化机器人方案；不计划从零建完整角色动画管线 |
| 远程协作或国庆可用时间下降 | 小任务异步交付，上传场景+录像+说明；返校不是前置条件；林晓风离校前交清单 |
| 新人模块延期 | 先减功能：流程改固定顺序、UI减装饰、敌人只一类；只把小范围难点交绯云，不整体转移工作量 |
| Y.sir/豆橛子/备注“？”成员未确认 | D1确认；未确认前不以表中假设作为承诺；低于预算即重排，不靠兼任策划补全 |
| FKR梧桐后来加入 | 先完成工程启动和一个小任务，再分配配置/回归或独立可选功能，不改关键路径 |
| 名义上完成，但无法启动/通关/提交 | D5起每日可运行包；D16/D19干净机器回验；D20保存实际提交凭证 |

**裁剪顺序：**主动时停/连斩/重型/随机地图等P2不启动 → 不启动P1额外技能 → 取消远程敌人变体 → 减少房间数量与视觉装饰 → 保住兔子跳、高速攻击、简化parry、单敌人、完整胜负与重开。

如果D8仍无法跑通最小流程，必须向队长明确报告范围不可达；允许重新定P0，但必须记录批准的删改，而不是在D20声称全案完成。

## 十、团队执行规则与队长待确认事项

- 每日异步更新三句话：完成了什么、下一步做什么、卡在哪里。每2天一次短集成检查，不占用所有人的长会议。
- 一人一分支、一个PR解决一个任务；共享接口先沟通。场景指定编辑主责，模块用独立场景/Prefab交付，避免多人同时改同一个大场景。
- 若确认为Unity项目，项目设置/包版本由主程序统一管理，资产与对应.meta共同提交；不提交缓存/构建目录。不在本计划阶段擅自更新引擎或插件。
- 关键缺陷至少记录：版本、复现步骤、预期/实际、截图或录像、负责人。启动失败、无法通关、无法重开是阻断问题。
- 本计划以单一项目、最小依赖、已有工具为原则，不另建任务平台、技能框架或程序化动画系统。

**D1需队长确认：**
1. 实际D1、活动截止时间/时区、交付平台、引擎版本与目标设备。
2. 是否批准本计划范围裁剪及5—8分钟目标；由谁担任最终制作/范围负责人。
3. 每人的实际投入、远程方式和技能情况，特别是Y.sir、豆橛子、炡凧及备注“？”的成员。
4. 现成模型/动画/音频的可用性与授权；中台可提供什么，但不计入保底。
5. 关键岗位不可用时的缩减版目标，以及D20的实际提交负责人。

完成标准不是“每个人都有很多任务”，而是：核心模块有明确主责、所有人产能没有重复计算、前置依赖能按时交付、D20确实交付可玩的完整版本。
