## 1. 目标与取舍

**21 天交付一段完整可玩的流程，不交付通用游戏框架。** 优先验证“跑跳提速 → 高速攻击 / parry → 能量技能 → 继续移动”的核心循环。

- 保留现有 `PlayerMotor`、相机、参数资产和测试；与备选 `CharacterMovement` 互斥，不重写移动模型。
- Unity 2022.3.33f1c1、URP 14.0.11、旧版 Input Manager、60Hz 固定逻辑步保持不变；不新增第三方依赖。
- 数值进 SO / Inspector；运动由运动学控制器完成，不用刚体力模拟角色手感。
- 先做一个敌人、一个房间、一次完整战斗，再扩展内容；每阶段都有可运行版本。
- 本期不做通用事件总线、服务注册器、动态技能装卸、通用行为树、程序集拆分和大规模目录迁移。
- 房间先手动拼接验证动线。原策划有随机地图设想，选型稿记录为手动拼接；D1 确认比赛版范围，不将两者视为同一需求。

## 4. 开工前统一的接口约定

### 4.1 输入与动作控制（3C + chq）

- **Update 统一采样，FixedUpdate 消费快照和缓冲。** Ctrl 的按下与按住状态必须独立于 Shift；修改滑铲进入、维持和退出逻辑，移除“按住 Shift 松开 W 即滑铲”的旧判断。
- 复用 `IPlayerInput` 测试入口，但先修 `InputBuffer`：先匹配全部条件，再消费触发键，避免折返检查失败却吞掉加速右键。普通攻击、闪避、跳跃也纳入统一仲裁。
- 同一按下沿只消费一次。动作暂不可执行时，输入保留到缓冲过期；暂停 / 重开清空旧输入，不在恢复时补发。
- **Motor 唯一负责速度、胶囊和位移。** 战斗通过命令请求冲量、水平速度设置、转向或临时重力覆盖，不能直接移动 Transform。
- 普通跳跃、滑铲、蹬墙先留在 Motor；战斗统一决定是否允许它们取消当前动作，不能绕过取消规则。动作结束 / 打断时释放移动限制与重力覆盖。
- 高跳记忆、高速普攻落地清动量、连斩清速与滞空、推斩速度衰减必须通过同一移动入口完成。联调时逐项验证，不另起第二套移动逻辑。

**固定步顺序：** 更新时间 → 输入仲裁 / 动作切换与扣费 → 移动 → 积能 → 命中结算 → 房间状态。由组件执行顺序或明确调用保证，不另建通用调度框架。

### 4.2 玩家攻击（chq + 空气）

一个 `PlayerCombat` 管理当前攻击、前摇 / 生效 / 后摇；攻击参数放 SO，行为按需拆类。不先做通用技能宿主、挂载槽或技能选择系统。

**取消规则只保留一份配置，按“动作变体 + 阶段 / 窗口 + 目标动作 + 条件”判断。** 常态与高速普攻在起手时确定变体；高速伤害取挥出时速度快照，不能在每次命中时重新取值。

| 当前动作 | 必须支持的规则 |
| --- | --- |
| 常态普攻 | 后摇可被闪避、非原地跳取消；不可普攻自取消；与连斩、推斩的衔接按各自规则处理 |
| 高速普攻，未触发 parry / 断肢 | 仅连斩、推斩、折返可取消；不能套用常态的闪避 / 跳跃规则 |
| parry / 断肢后的普攻派生 | 开放闪斩；派生窗口长度及适用阶段由策划确认 |
| 闪斩 | 支持普攻衔接、后摇接连斩；常态 / 高速普攻的适用范围 D1 确认 |
| 连斩 | 前段可接普攻；收尾大斩后的后摇不可取消 |
| 推斩 | 与普攻相互取消 |
| 滑铲 | 可被前跳取消，不等同于任意跳跃 |

先验证激活条件、取消权限、冷却与能量，再统一提交扣费、消费输入及动作切换；失败不扣费，也不打断原动作。冷却按时间戳计算，不能只在当前动作 Tick 时恢复。

时停单独记录持续效果，不占当前攻击状态；是否允许边时停边攻击、组合键是否结束时停，由 D1 玩法确认决定，不扩展成通用并行技能框架。

### 4.3 能量与时间（Ysir + 3C；SYA 协作调参）

- 能量从 Motor 外迁，统一提供读取、`TrySpend`、增加与复位入口；Motor 原只读能量属性可暂时转发，避免 HUD / 测试同时重写。
- 策划公式中的速度统一使用“水平速度 / 地速阈值”。迁移现有绝对速度参数时同步换算系数，避免无意改变积能曲线。
- `TimeManager` 分开提供渲染帧与固定步时间。Motor 及其滑铲等内部方法全部使用同一固定步 dt，不再混读帧缓存。

| 逻辑 | 时间约定 |
| --- | --- |
| 玩家移动、攻击、冷却、无敌与积能 / 持续耗能 | 玩家逻辑时间；玩家冻结时不执行动作或资源结算 |
| 敌人、投射物、世界机关及其动画 | 世界逻辑时间；移动和动画实际执行端都要接入，不能只缩放 AI 决策 |
| 输入缓冲、UI、相机 | 不缩放时间；暂停时不接受游戏动作 |
| hitstop / 临时时间效果的解除计时 | 不缩放时间，避免效果把自己的结束计时冻结 |

60Hz 基准下按策划每 tick 数值结算；缩放时，持续资源变化乘以“所属逻辑 dt / 基准 tick 时长”。一次性扣费不缩放。积能在本 tick 移动之后执行，技能使用 tick 开始时已有的能量。

时间缩放按来源登记 / 释放，同层取最小值；暂停、时停与 hitstop 不互相覆盖。效果取消、对象失效和重开均释放自身来源。parry 时缓是否影响玩家层、时停作用范围由 D1 确认。

### 4.4 命中与反馈（空气 + chq + leo）

- 统一伤害信息：攻击者、目标、攻击实例 / 段数、伤害类型、伤害值、命中点与击退。
- **先独立判定攻击对攻击的 parry，再判定未被化解的伤害与无敌。** 无敌不能阻止继续 parry；投射物的受 parry 范围与伤害范围分开配置。
- 每段攻击对同一目标去重，多段攻击显式换段。高速攻击 / 投射物检测覆盖前后位置间的路径，不能只依赖瞬时触发器重叠。
- 物理查询只收集候选，在明确的逻辑结算阶段处理；不要假设调整脚本顺序就能改变物理回调时机。
- 滑铲免疫投技 / 投射物，不等于全无敌；受击形状与移动碰撞胶囊分开。轻型敌人死亡后移除阻挡，撞击惩罚遵循攻击 / parry / 滑铲豁免。
- 伤害、无敌、击退、时间效果立即通过接口生效；音效 / 特效通过实例事件通知，不把关键逻辑推迟到渲染帧末。
- HUD 绑定时读取完整状态，再监听带主体标识的血量 / 能量事件；速度连续读取只读接口。订阅随绑定解除，重开不全局清空常驻订阅。

### 4.5 关卡与复位（y_mmm + 协作成员）

- 第一版一个房间：刷怪 → 战斗 → 清场开门 → 到达终点；再扩展房间、机关和检查点。
- leo 提供敌人死亡通知和场地级攻击配额；死亡 / 打断 / 禁用时归还配额。首版只约束已需要的远程攻击。
- **跌落回检查点、死亡重试、整局重开分开处理。** 跌落按策划扣血并快速回位，不默认重置敌人或整个房间；死亡重试与整局重开的恢复范围 D1 确认。
- 所有回位入口清理输入、攻击判定、临时移动限制与时间效果；血量、能量、房间进度按对应复位策略处理，不全部清零。

## 6. 验收清单与 D1 待确认项

### 必须通过

- Ctrl 下蹲 / 滑铲与 Shift 冲刺不互相触发；右键组合键不吞键，同一按下沿不重复执行。
- 使用相同 tick 输入序列，在不同渲染帧率下比较移动结果；保留现有三项 PlayMode 回归，并与 `Tools/movement-sim` 对照。不能仅靠修改 dt 或测试快进设置宣称确定性。
- 常态 / 高速取消规则分别测试；能量不足不扣费、不取消原动作；高跳记忆和落地动量行为符合约定。
- parry 可连续触发；多 Collider 不重复伤害，多段攻击正常命中，高速攻击不漏过目标。
- 世界冻结后敌人 / 投射物停止；玩家层按确认规则运行；暂停不积能、不耗能、不出招，退出效果后时间正常。
- 跌落、死亡重试、整局重开分别验收；重复重开后无残留攻击、无敌、时间来源、配额或重复订阅。
- 实际构建能从开始玩到结束，能够暂停和再次游玩；以构建验收，不只看编辑器。

### D1 确认，未确认不作为已定玩法

1. 各意向人员的实际主责与投入；UI、音频、构建负责人。
2. 时停作用层、与攻击 / 右键组合键的共存规则；parry 时缓的作用层与持续时间。
3. 闪斩的派生窗口和可衔接普攻变体；未明确的取消边界。
4. 手动房间是否为比赛版正式范围；死亡重试的敌人、血量、能量与进度恢复规则。
